# 漫遊簡報 Wander Deck — 給 AI 的操作手冊

你（AI）是操作者，使用者只負責提供照片和說想要什麼。
使用者多半不會寫程式：**跟他講話用白話，不要貼指令叫他跑**，你自己跑。

`$WD` 代表這個專案的根目錄（有 `engine/`、`scripts/` 的那一層）。

## 成品長什麼樣

- 一個資料夾就是一份簡報；裡面每個子資料夾是一個「主題」，可以再分一層子主題。
- 打開後：開場頁（可選，照順序翻）→ 主畫面（主題小卡，想點哪個就點哪個）→ 主題內的照片牆 → 點照片放大、有放大鏡。
- 可選：背景音樂（循環、換頁不中斷、右下角播放鈕和音量拉桿）、展示牆（幾張照片並排放大、不能點）、結尾 QR code 頁（左下角按鈕進入）、開場動畫（插畫裡的東西會動、標題像旗子飄）。
- 全部是本機檔案，整個資料夾複製給別人就能看，不用網路、不用安裝。

## 簡報資料夾的結構

```
我的簡報/
  簡報.html                ← 使用者點這個看（引擎，不要手改）
  打開簡報.command          ← 全螢幕＋音樂自動播放（上台用這個）
  更新簡報.command          ← 使用者自己加照片後點這個
  deck.json                ← 所有設定，你主要改這個
  01 第一個主題/ …照片、影片
  02 第二個主題/子主題A/ …
  _assets/                 ← 背景、LOGO、音樂、開場圖（底線開頭的資料夾不會變主題）
  _wander/                 ← 產生出來的東西（build.py、縮圖、大圖、data.js），可刪掉重建
```

- 主題名稱＝資料夾名稱，網頁上會自動拿掉開頭的排序編號（`01 `、`1.`）。
- 照片可以直接是 HEIC，不用先轉 JPG。影片 MOV/MP4 直接放。
- **產生的縮圖和大圖會自動轉正、清掉 GPS 位置和拍攝資訊。** 原始照片不會被改。

## 工作流程

### 1. 先問清楚（一次問完，不要一題一題擠牙膏）

- 照片在哪個資料夾？簡報要做在哪裡？（建議做在新資料夾，把照片「複製」進去，不要動原本的相簿）
- 簡報標題？
- 主題怎麼分？（已經分好資料夾就照資料夾）
- 要不要：開場頁、背景音樂、背景圖、LOGO、結尾 QR code？
  沒有素材的就先跳過，之後隨時可以加。
- 使用者第一句話已經講清楚的就不要再問，直接做。

### 2. 建立

```bash
$WD/scripts/new_deck.sh "<簡報資料夾>" "<標題>"
```
然後把照片按主題放進子資料夾、素材放 `_assets/`，編輯 `deck.json`（格式見 `$WD/docs/deck-json.md`）。

### 3. 產生並檢查

```bash
python3 "<簡報資料夾>/_wander/build.py" --check   # 只檢查設定，有 ⚠️ 就先修
python3 "<簡報資料夾>/_wander/build.py"           # 產生縮圖、大圖、data.js
```
照片很多時第一次會跑幾分鐘，之後只處理新加的。

### 4. 自己先看過，才交給使用者

```bash
$WD/scripts/preview.sh "<簡報資料夾>" "#/" /tmp/home.png             # 主畫面
$WD/scripts/preview.sh "<簡報資料夾>" "#/<主題資料夾名>" /tmp/t.png    # 某個主題
$WD/scripts/preview.sh "<簡報資料夾>" "" /tmp/p1.png 1920x1080 --freeze 2   # 開場第 1 頁，動畫停在第 2 秒
$WD/scripts/preview.sh "<簡報資料夾>" "#outro" /tmp/o.png             # 結尾頁
```
**每次改完都要讀截圖確認**，至少看大螢幕（1920x1080）和筆電（1440x900）兩種比例。
截圖只拍得到某一瞬間：畫面剛切換時會有淡入，照片看起來半透明是正常的。

### 5. 交給使用者

- 叫他點兩下 `打開簡報.command`（上台用：全螢幕、音樂自動播）。
- 告訴他：自己加照片後點兩下 `更新簡報.command`，再按 ⌘R。
- **動畫的速度、幅度一定要請他用眼睛看**，截圖看不出來。他說「太快／太大／不夠明顯」就調 `deck.json` 裡的 `speed`、`amount`。

## 常見要求 → 怎麼改

| 使用者說 | 你做的事 |
|---|---|
| 主題換順序 | `topics.order` 寫資料夾名稱 |
| 某主題不要出現 | `topics.hidden` |
| 主題改名（資料夾不動） | `topics.labels`：`{"資料夾名": "網頁上的名字"}` |
| 主題改名（連資料夾） | 改資料夾名，並同步改 `order`／`walls`／`labels` 裡的舊名字 |
| 這頁照片少，要大大的並排、不能點 | `topics.walls` 加上資料夾名（適合 2–4 張） |
| 換背景音樂 | 檔案放 `_assets/`，改 `music.file`；起始音量 `music.volume`（0–100） |
| 開場加幾頁（Keynote／Canva 做好的） | 匯出 PNG 放 `_assets/`，`intro` 加 `{"type": "image", "src": "..."}` |
| 開場要會動 | 見下面「開場動畫」 |
| 結尾放 IG／網站 QR code | QR 圖放 `_assets/`，先 `$PY $ST qr <圖>` 解碼確認網址對，再設定 `outro` |
| 介面文字改英文 | `text`（見 docs/deck-json.md） |

## 開場動畫（最花工夫，照這個順序）

素材：一張插畫背景（建議 16:9、寬 ≥1600px），標題去背 PNG（可選）。

1. 第一次先裝工具：`$WD/scripts/setup_scene_tools.sh`
   之後用 `PY=~/.wander-deck/venv/bin/python`、`ST=$WD/scripts/scene_tool.py`。
2. **找座標**：先看整張圖，挑出適合動的東西，再對每一塊跑
   `$PY $ST grid <背景> x0,y0,x1,y1 /tmp/g.png` 讀格線找精確像素座標。
3. **會移動或擺動的東西**（吊燈、動物、人、車）→ 剪成獨立圖層，原位補背景：
   `$PY $ST cut <背景> x0,y0,x1,y1 _assets/scene/燈.png --scene _assets/scene [--dark 200] [--line x,y0,y1]`
   - `--dark` 是「比多暗才算物件」：剪不到就調高、剪太多背景就調低。
   - 吊燈的鍊子太細剪不到：用 `--line` 補一條直線。
   - 用 `$PY $ST preview 圖層.png /tmp/p.png` 檢查剪得乾不乾淨；
     再把 `_assets/scene/bg.png` 那一塊放大看，原位要沒有殘影（有就加 `--grow 3 --grow-down 6` 重剪）。
   - 重剪前先刪掉 `_assets/scene/bg.png`，不然會在已經補過的圖上再補一次。
4. **原地飄動的東西**（樹葉、旗幟、布）→ 切一塊羽化區域，不挖空：
   `$PY $ST region <背景> "x,y;x,y;..." _assets/scene/葉.png --scene _assets/scene`
   **region 要在所有 cut 做完之後才切**（它是從補好的 bg.png 切的）。
5. 每個指令最後印的 JSON 直接貼進 `deck.json` 的 `scenes.<名稱>.layers`，加上 `effect`：
   - `swing` 鐘擺（`amount` 角度、`speed` 秒、`origin` 支點，吊燈用 `"46% 0"` 這類上方中點）
   - `walk` 往右走再淡出重來（`amount` 走多遠，是圖層自己寬度的 %；`speed` 一趟幾秒）
   - `breeze`／`breeze-soft` 微風、`flutter` 旗幟（比較快）、`float` 上下漂
   - 疊放順序＝陣列順序（樹葉放前面＝在最底下）。
6. 場景背景改用 `_assets/scene/bg.png`（已經挖掉會動的東西）。
7. 標題：`intro` 那頁的 `title`，`effect: "flag"` 會像旗子由左往右飄。
   位置 `at: [left%, top%, width%]` 是相對畫面；要對齊使用者 Keynote 版面時，
   可以用 OpenCV `matchTemplate` 把標題圖在 Keynote 匯出圖上找出位置再換算百分比。
8. 同一個 scene 可以給好幾頁用（背景一樣、標題和拍立得不同）。

## 踩過的坑（不要重蹈覆轍）

- **標題飄動不要改成「切直條」或 SVG 扭曲**：切直條會有細細的接縫線（條數加倍反而更糟），SVG 扭曲會把字形扭歪。引擎裡的 canvas 逐像素畫法是試到最後唯一合格的。
- **直接點開本機 HTML（file://）時，CSS mask 用本機圖片會被瀏覽器擋掉**。要遮罩就內嵌成 data URI。
- **瀏覽器不准網頁自己出聲**。要一打開就有音樂，只能用 `打開簡報.command`（帶自動播放參數開 Chrome）；直接點 HTML 就得等使用者先點一下。
- **`sips -g orientation` 讀不到 iPhone 照片的方向**，引擎自己讀 EXIF。你自己寫轉檔也別信 sips 這一項。
- **放大鏡的位置要用照片「最後停住」的大小算**，不要量正在放大動畫中的元素。
- **CSS class 名稱撞到**會讓某個元素莫名其妙多一圈白框（拍立得照片曾經套到縮圖的樣式）。
- **拍立得照片要塞滿到相框紙面底下**，相框內緣半透明的陰影疊在淺色背景上看起來像白邊。
- 下載的音樂檔先看大小，**0 KB 就是下載失敗**（build.py 會警告）。
- 使用者說的資料夾名稱可能已經被他自己改過了：**動手前先 `ls` 看現況**。
- 刪東西一律用 `trash`（丟垃圾桶，救得回來），不要 `rm` 使用者的照片。

## 回報使用者時

- 用白話講「現在簡報長怎樣、要他看哪裡」，不要貼 JSON 或錯誤訊息全文。
- 沒親眼確認的（動畫快慢、影片有沒有聲音、實際掃 QR code）明講「要請你看一下」。
