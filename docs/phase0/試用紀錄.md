目的：在動手寫 App 之前，確認「Pi＋ChatGPT 訂閱」這條路真的走得通。

## 結論

| 要確認的事 | 結果 |
|---|---|
| Pi 用 ChatGPT 訂閱登入 | ✅ 已登入可用（`pi auth check --provider openai-codex` → ready） |

## 細節

### 1. 看圖分主題（`pi -p`）

- 素材：`examples/tokaido` 的 18 張浮世繪（CC0），用 `sips` 縮成長邊 512px，全部加起來 940KB。
- 模型：
  - `gpt-5.5` ✅ 9.3 秒。
  - `gpt-5.4-mini` ❌ 錯誤訊息：「not supported when using Codex with a ChatGPT account」。**訂閱帳號不能用 mini**，App 預設用 `gpt-5.5`。
- 結果（AI 自己分）：
  ```json
  {"title":"浮世風景紀行","subtitle":"在雪、山、海與驛路之間，重訪江戶旅途的詩意。",
   "topics":[{"name":"雪中名所","cover":"img13"},{"name":"水岸月色"},{"name":"驛路行旅"},{"name":"富士遠眺"},{"name":"屋內人情"}]}
  ```

### 2. 指定主題（`pi --mode rpc`，模擬 App）

- 腳本：[`rpc_test.py`](rpc_test.py)（Python 模擬；Swift 版用 `Process`＋`Pipe` 照做）。
- 指定「雪／夜／山與河」：雪 4/4 全對（多收 1 張）；夜只抓到 2/4（兩張水邊夜景被分到「山與河」）；山與河 5/5 全對。
- 啟動參數：`--no-tools --no-session --no-context-files --no-skills --no-extensions --no-prompt-templates`，讓 Pi 只當「看圖回答」用，不會去碰使用者的檔案。

### 3. 畫圖

- Pi 0.85.1 的畫圖功能只接 OpenRouter（要另外付 API 費），不吃 ChatGPT 訂閱。
- Codex CLI 0.150.1（已用 ChatGPT 登入）的 `image_generation` 可用：
  `codex exec --skip-git-repo-check --sandbox workspace-write "<畫圖指令>，存成 xxx.png"`
- 試畫結果：[`水彩試畫.jpg`](水彩試畫.jpg)，1672×941（16:9），68 秒。吊燈、樹都適合拿來做會動的圖層。
- **影響規劃**：第 2 階段的水彩素材可以由我直接用 Codex 畫，園長只要挑圖、看動畫點頭，不用自己手動去 ChatGPT 畫。
  這只是**開發時做素材**用；使用者的 App 不需要畫圖功能。
